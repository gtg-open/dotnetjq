# Porting status

## Current state

DotNetJq is a source-traceable managed port of jq/libjq. Its semantic
source of truth is jq 1.8.2, tag `jq-1.8.2`, commit
`34f7186b86743a083a589741b6cea95293524108`.

Manifest schema version 2 is release-closed: all 82 file mappings and every
dependency, auxiliary implementation, and machine-mapped test category have a
terminal status. `done`/`semanticParity: true` is always scoped to the declared
jq-visible behavior; intentional `OMITTED` entries remain
`done`/`semanticParity: false` with explicit reasons. This is not a claim of
unscoped C ABI, VM, generator-state, or replacement-engine identity.

Toolchain and package boundary:

- .NET SDK `10.0.400` (`global.json`), target `net10.0`.
- C# `latest`, which is C# 14 with the pinned SDK.
- The managed API NuGet package ID is `DotNetJq.Library`; its assembly and
  namespace remain `DotNetJq`. The separate CLI package and command use
  `dotnetjq`, avoiding a case-insensitive package/tool identity collision.
- NuGet packing requires explicit publisher `Authors` and Git `RepositoryUrl`
  inputs. Release verification rejects missing, placeholder, or unequal
  identity metadata across the library, selector, and all RID packages.
- Both managed library assemblies declare `IsAotCompatible` and `IsTrimmable`,
  build with the SDK AOT/trim analyzers enabled, and ship their generated XML
  API documentation in the exact `DotNetJq.Library` package inventory.
- The library package is managed-only: no process launch, P/Invoke,
  native-library load, libjq dependency, jq executable, network client, or
  absolute upstream path. The `dotnetjq` application uses that library and
  never launches the reference jq executable.
- GNU C Library-derived gamma code is confined to the separately built,
  `LGPL-2.1-or-later`, ABI-replaceable `DotNetJq.GlibcCompat.dll`; the package
  includes its exact license, complete corresponding source, and offline
  rebuild/replacement instructions.
- The package builds and executes with the upstream checkout hidden, jq made
  unusable, and network disabled; the same gate rebuilds and substitutes the
  gamma component without changing `DotNetJq.dll`.
- The CLI can be distributed as a .NET 10 RID-selected tool or as self-contained
  NativeAOT archives for Windows, Linux/glibc, Linux/musl, and macOS on x64 and
  arm64. NativeAOT corresponding-source and relink requirements are separately
  enforced because the gamma component is folded into the executable.

## Architecture classification

Production follows this path:

```text
jq source -> generated managed scanner/parser -> block/inst compiler IR
          -> binding and 16-bit bytecode lowering -> direct stack/frame/fork VM
          -> jq_start / jq_next lifecycle

argv/stdin/files/environment -> DotNetJq.Cli adapter -> the same managed core
                             -> stdout/stderr bytes and jq-compatible exit status
```

The compiler and executor are direct `PORT` mappings. Production lowering emits
jq's variable-length 16-bit opcode form and production execution consumes it
through the mapped negative-offset persistent stack, closure frames, forkpoints,
and `ON_BACKTRACK` dispatch. The former AST/iterator evaluator and duplicate
builtin implementation were deleted; there is no fallback execution engine.

The production scanner is deterministically generated by pinned GPLEX from
the committed managed `src/DotNetJq/Grammar/lexer.l`. Its 53 ordered rules and
six start conditions are structurally checked against jq 1.8.2; its C# actions
remain a language-specific manual port and its DFA/runtime is not Flex-identical.
The production parser is deterministically generated by pinned GPPG from the
committed managed `src/DotNetJq/Grammar/parser.y`. Its 167 upstream alternatives
produce 169 GPPG rules and 312 LR states with zero conflicts. Marked
`%precedence` declarations are generated once as `%left` and once as `%right`;
byte-identical tables prove that the stand-in associativity is not consulted.
Both maintained grammars contain C# action ports and immutable upstream
provenance; jq's original C-action files are not committed. Production has no
fallback to a handwritten or template-expanded parser.

`PARSER_GRAMMAR_COVERAGE.json` provides machine-checked ownership coverage for
every pinned lexer rule, token, precedence declaration, and production. The
generated parser preserves jq's observable stack boundary: 9,994 balanced
parenthesis levels are accepted and 9,995 produce the bounded
`jq: error: memory exhausted` diagnostic.

See `EXECUTOR_ARCHITECTURE.md`, `EXECUTE_VM_IMPLEMENTATION_MAP.md`,
`EXECUTOR_BYTECODE_AUDIT.md`, `REFERENCE_COUNT_OWNERSHIP_MAP.md`, and
`PARSER_GENERATION_AUDIT.md` for the exact boundaries. Native allocation
addresses/C layout and refcount-address trace identity remain excluded.

## Implemented compatibility surface

- Managed jq value representation with source-shaped logical ownership for
  allocated invalids, literal numbers, strings, arrays, and objects: `jv_copy`/`jv_free`
  reference counts, consuming jq APIs, copy-on-write collection/string
  mutation, UTF-8 byte-backed strings with cached seeded hashes, array
  offset/size/capacity views, and object slots/buckets with owning raw `jv`
  keys and values. Parsing, printing, comparison, containment, path/update
  operations, generators, closures, modules, errors, and formats use that same
  value surface. Direct array mutation and iterative path updates share jq's
  exact `(INT_MAX >> 2) - array offset` rejection boundary; the former managed
  `int.MaxValue / 16` path-only pre-cap is removed.
- Direct VM ownership separates jq allocation refcounts from physical stack-block
  sharing. Saved forkpoints share persistent data/frame blocks without eagerly
  incrementing every `jv_refcnt`; `stack_pop` copies a value while the block is
  still shared and moves it on final release, exactly as upstream. Typed CLR
  payloads are side-tabled by jq-shaped logical stack address. Exact native C
  layout and refcount address trace text remain excluded, but `jv_copy`/`jv_free`
  behavior that affects counts or copy-on-write is not delegated to CLR GC.
- Compiler-produced bytecode records a managed-only, bottom-up summary of whether
  `$ENV` constant slots exist anywhere in each subtree. Execution graphs without
  `$ENV` skip snapshot restoration, explicit environment materialization, and
  replacement traversal entirely. Graphs with `$ENV` retain a fresh environment
  owner on every explicit-environment execution and the existing compile-time
  restoration semantics; by default, `$ENV` remains the compile-time process
  snapshot while every `env` invocation reads current ambient process state.
- Per-program `OwnedJqAstConstants` copies compiled constants before parsed-tree
  release and reproduces final `bytecode_free` lifetime. Parse/link ledgers free
  reduced literals, `MODULEMETA`, `DEPS`, imported module trees, and data values
  on failure or cancellation; successful data-import slots transfer to
  `OwnedJqScope` and release with program teardown.
- Exact embedded upstream `builtin.jq`: 9,631 bytes, 106/106 source definitions
  bound into each compiled program.
- Public `builtins/0` inventory: 226/226 jq 1.8.2 signatures, with no missing or
  extra public entries.
- Managed libc-time compatibility for the pinned Linux/glibc-2.39 C-locale
  contract: complete `strptime`/`strftime` directive and raw-`tm` behavior,
  `mktime`/`gmtime` normalization and extreme ranges, microsecond `now`, plus
  IANA TZif and POSIX-TZ offsets, abbreviations, invalid identifiers, and DST
  gaps/folds. The source-shaped `mktime` proxy preserves the six-probe loop,
  explicit-`tm_isdst` correction/failure, raw-second post-adjustment, and
  stateful offset guess across negative-DST and date-line gaps. The 125-case
  glibc matrix freezes platform-independent expectations; its four host-TZif-
  sensitive gap rows compare exactly with the same-host pinned jq oracle. It
  also covers partial `%hu` POSIX parsing and far-year C arithmetic. The
  implementation is NativeAOT-safe and does not reflect over
  private runtime fields; `TIME_COMPATIBILITY.md` records the explicit
  locale/leap-second/absolute-path/cross-libc and Windows no-TZif exclusions.
- Regex operations behind a jq-shaped `System.Text.RegularExpressions` proxy,
  including compatibility logic for exercised Oniguruma syntax, Unicode,
  captures, options, and zero-width advancement. The source-shaped event
  runner enforces Oniguruma's deterministic 10,000,000-retry per-match limit,
  resets it for every candidate, and preserves zero as the unlimited form.
  A conservative structural pre-router sends covered exponential and long-linear
  default-boundary patterns to counted execution. If retry-relevant grammar is
  not accepted by that runner, execution fails closed before opaque .NET
  backtracking. The audited valid high-risk grammar now includes numeric,
  relative, named, and whole-pattern calls; capture levels and conditionals;
  nested absent ranges; class-context and control escapes; `\G`; and fixed-width
  lookbehind calls/backreferences/reduction. Exhaustive proof over every possible
  exotic Oniguruma program remains an explicit audit qualification.
- Managed decNumber-style literal-number preservation and jq-compatible numeric
  behavior over the exercised surface.
- Modules and data imports through an explicit `IJqFileSystem`/
  `JqModuleResolver` capability, including search/origin behavior, metadata,
  cycle detection, cancellation checks, immutable search/content snapshots,
  and optional graph limits. The physical `System.IO` implementation documents
  its non-atomic check/open TOCTOU window and is not presented as an OS sandbox.
- Stateful library behavior for `input`, `inputs`, input positions,
  `debug`, `stderr`, origin/search metadata, `modulemeta`, `halt`, and
  `halt_error`, without ambient standard streams, filesystem, or process
  termination. `$ENV`/`env` retain native ambient environment behavior unless
  the caller supplies the explicit sandbox extension.
- Pull-based and materializing public APIs with explicit terminal outcomes and
  execution resource options. `MaxInputBytes` is one aggregate UTF-8 budget over the
  primary input plus every value or error JSON payload returned by `input`/`inputs`;
  exhaustion remains sticky if a jq handler catches the limit error.
- Iterative or guarded handling of jq's 10,000-level JSON/path/containment/
  equality/comparison/object-merge boundaries covered by focused tests.
- Parser-lowered helper calls remain lexically shadowable exactly as in jq:
  recursive descent, formatting/interpolation, unary and binary operators,
  assignments/updates, and label error handling use jq call semantics when a
  nearer definition exists while retaining optimized managed fallbacks for
  the canonical helpers.
- `dotnetjq`, a managed port of `src/main.c`'s public behavior: jq-style option
  bundling and interspersing; stdin and ordered files; raw/slurp/sequence/stream
  parsing; filter and module files; named/positional arguments; formatting,
  ANSI color and NUL framing; diagnostics; halt behavior; and exit statuses.
- As in `main.c:664` and `util.c`, the outer primary-input loop and jq's
  `input`/`inputs` builtin share one forward reader through `jq_set_input_cb`.
  That CLI-only callback transfers the parser's owned `jv` directly, including
  invalid-with-message parse errors and current filename/line state; it does not
  convert through the public `JsonElement` capability transport. The public
  `IJqInputSource` API and its aggregate `MaxInputBytes` policy are unchanged.
- Parsed, raw-line, and raw-slurp CLI input all consume one direct port of
  `jq_util_input_read_more`: a 4,091-byte `fgets` payload followed by only the
  required UTF-8 tail bytes. This preserves jq's pre-parse line state, delayed
  EOF/source transition, raw partial-line continuation across files, per-buffer
  malformed-UTF-8 repair, and even the native rule that a newline consumed by
  the UTF-8 tail `fread` is not counted. Parsed slurp and callback end positions
  therefore identify the final source and all native-counted blank lines.
- Direct command use on Unix, PowerShell 7, and Windows PowerShell 5.1. The
  release workflows require byte-oriented process tests for all eight supported
  64-bit NativeAOT targets; this host locally builds and executes the
  framework-dependent and `linux-x64` NativeAOT forms.
- The release bundle gate installs its exact `dotnetjq` selector and matching
  RID package from a local-only feed on native Windows x64 and ARM64 runners.
  It explicitly selects the matrix architecture, verifies the resolved package
  and command shim, and requires the full PowerShell contract under both
  PowerShell 7 and Windows PowerShell 5.1; a missing shell cannot become a skip.
- Managed compatibility implementations of `--run-tests`,
  `--debug-dump-disasm`, `--debug-trace`, and `--debug-trace=all`. Test fixtures
  execute through the managed compiler/bytecode VM; disassembly reads the
  production bytecode through `jq_dump_disassembly`, while trace output follows
  bytecode VM events.

The external jq executable is used only by test tooling as an oracle. The
managed CLI does not install a `jq` alias automatically and does not expose the
native allocator/`FILE*` fault-injection machinery, Valgrind accounting, signal
behavior, or exact native bytecode/program-counter/stack/refcount trace identity.

## Public API boundary

The convenience API is:

```csharp
var program = JqProgram.Compile(filter);
IReadOnlyList<JsonElement> outputs = program.Execute(json, executionOptions);
```

The explicit stateful API adds:

- `JqProgram.ExecuteDetailed` for materialized outputs plus a
  `JqExecutionOutcome` (`Completed`, `Halted`, or `RuntimeError`);
- `JqProgram.StartExecution` and `JqExecution.TryRead` for lazy pull-based
  consumption;
- one active execution per `JqProgram`, with sequential reset/reuse of its
  jq-shaped state and concurrent execution through independently compiled programs;
- `JqExecutionCapabilities` with explicit `IJqInputSource`, debug sink, and
  standard-error sink;
- `JqExecutionInput`/`JqInputPosition` for caller-owned source position;
- `JqCompilationOptions` for `ProgramOrigin` and `JqModuleResolver`;
- `JqExecutionOptions` for timeout, cancellation, aggregate primary-and-capability
  input bytes, output bytes/count, recursion, VM execution transitions, regex timeout,
  and an immutable explicit environment snapshot. `MaxGeneratedValues` is
  affirmatively absent because jq has no generated-intermediate-value event;
  `MaxOutputValues` counts yielded outputs and `MaxExecutionTransitions` counts VM
  instruction transitions. The transition budget and environment replacement are
  specification-authorized, opt-in managed host extensions, not upstream jq requirements;
- `JqModuleResourceLimits` for unique dependency count, aggregate imported
  bytes, and dependency depth. These limits, resolver cancellation, and the optional
  per-file cap are likewise opt-in managed host extensions with inactive defaults.

Plain `JqProgram.Compile(source)` denies module filesystem access. Default execution
retains jq's ambient `$ENV`/`env` timing and exposes no input/debug/stderr capabilities.
The package's public API runs independently of the reference checkout.

## Scope qualifications

1. **Parser/lexer parity is scoped to observable jq behavior.** Deterministic
   generation and the declared semantic audit are complete. Exact segmented
   string/interpolation tokens, UTF-8 byte
   locations/carets, invalid-escape spans and separate-run multiplicity,
   delimiter state, imported-source diagnostics, and a machine-checked grammar
   ownership report are covered. All 11 explicit Bison `error` alternatives
   have exact observable oracle cases and boundary controls. Bison state-table
   C-output identity and Bison's private table numbering/recovery internals are
   deliberately excluded. The production parser itself is generated GPPG and
   has no handwritten/template fallback.
2. **Special-math exactness is corpus-qualified.** The jq-visible `erf`,
   `erfc`, gamma, and Bessel families match a frozen 6,126-case exact oracle
   corpus. The replaceable gamma component additionally matches 1,366 direct
   deterministic records across `gamma`, `lgamma`, `lgamma_r`, and `tgamma`,
   including exact sign bits and signed-zero underflow. The managed fdlibm
   `acosh`, `asinh`, `atanh`, `expm1`, and `log1p` paths match a separate 2,596
   case binary64 corpus covering tiny-input, branch-neighbor, and
   maximum-finite boundaries. These offline comparisons use no tolerance or
   runtime oracle; they qualify the tested binary64 surface rather than claim
   a mathematical proof over every possible input.
3. **The direct compiler and VM are production.** Compiler-produced 16-bit
   bytecode, persistent stack blocks, closures, locals, forkpoints, normal/tail
   calls, and every executable forward/backtracking opcode are exercised directly.
   The jq `ARG_NEWCLOSURE` index boundary remains enforced: all 4,096 encodable
   closure slots (indexes 0 through 4,095) are accepted and a 4,097th is rejected.
   Managed object layout and malformed-bytecode assertion identity remain excluded.
4. **Regex parity is scoped to the jq-visible proxy surface.** The adapter
   passes the 1,029/1,029 focused slice, unchanged `onig.test` 47/47 and
   `manonig.test` 19/19 fixtures, and the complete declared 4,980/4,980
   differential inventory. The separate frozen-artifact audit matched
   92,589/92,589 primary rows and 62/62 isolated processes. The mapping is
   `done`/`semanticParity: true` within those measured surfaces. Native
   Oniguruma API, bytecode, allocator, engine architecture, and C ABI identity
   remain explicitly excluded.
5. **Time parity is pinned to a declared platform contract.** The complete
   C-locale directive/state/normalization surface and ordinary IANA/POSIX time
   zones match the Linux/glibc-2.39 oracle in 125/125 cases, including extreme
   years, negative-DST/date-line gaps, folds, and cached call order. Four
   host-TZif-sensitive gap rows use exact same-host oracle comparison; other
   expectations are frozen.
   Non-C era/alternate-digit data, leap-second `right/*` zones,
   absolute TZ file paths, other-libc extensions, host TZif/tzdata build or
   version drift, and Windows-only no-TZif naming/range remain explicit exclusions; see
   `TIME_COMPATIBILITY.md`.
6. **Resource controls are cooperative, not a sandbox.** Compilation lacks a
   source-size/time/AST policy; output limits apply after a value is produced;
   there is no general intermediate-memory cap; individual long operations may
   outlive a timeout until the next tick; regex cancellation is timeout-based;
   and physical filesystem checks have a TOCTOU window. Untrusted execution
   still needs host process/container CPU and memory limits.
7. **Manifest truth remains authoritative.** Passing fixtures never converts a
   structural `PORT`/`PROXY` mapping to complete semantic parity by inference.
   Consult `PORTING_MANIFEST.json` for every file's current status and strategy.
8. **CLI parity is public-behavior parity, not C implementation identity.** The
   option/input/output/module/error/status contract is mapped from `src/main.c`
   to `src/DotNetJq.Cli`. Product help/version text identifies `dotnetjq`;
   managed console, filesystem, globalization, and process APIs replace native
   implementation details. Managed test/disassembly/trace compatibility is
   structural; exact native VM trace identity and native memory/signal
   instrumentation remain outside the claim.

## Reproduce the release gates

The aggregate entry point is:

```sh
dotnet restore DotNetJq.sln
tools/verify-release.sh
```

It performs deterministic generation and manifest checks, a production-source
native/process/oracle audit, solution build and managed tests, all seven
official fixtures, crash-contained runner verification, NativeAOT parser/regex/
math smoke coverage, both differential corpora, and isolated-package validation.

Equivalent individual commands are:

```sh
tools/parser-gen/generate-gplex-lexer.sh --check
dotnet run --project tools/parser-gen/DotNetJq.ParserGen/DotNetJq.ParserGen.csproj -- \
  self-test --gppg dotnet-gppg
dotnet run --project tools/parser-gen/DotNetJq.ParserGen/DotNetJq.ParserGen.csproj -- \
  validate --parser src/DotNetJq/Grammar/parser.y --lexer src/DotNetJq/Grammar/lexer.l
dotnet run --project tools/parser-gen/DotNetJq.ParserGen/DotNetJq.ParserGen.csproj -- \
  check-generated-parser --parser src/DotNetJq/Grammar/parser.y \
  --output src/DotNetJq/Generated/Parser/JqGeneratedParser.g.cs
python3 tools/parser-gen/prototypes/parser/validate.py --audit-upstream
python3 tools/parser-gen/generate.py --check --upstream upstream/jq
python3 tools/generate_manifest.py --check --release
python3 tools/generate_fdlibm_elementary_corpus.py --check
tools/verify-compatibility.sh
tools/verify-cli-compatibility.sh
tools/DotNetJq.CompatibilityRunner/verify-isolation.sh
tools/native-aot-smoke/verify.sh
tools/aot-compliance/verify-relink.sh --version 1.0.0 --rid linux-x64
dotnet run --configuration Release --project tools/DotNetJq.DifferentialProbe -- \
  --seed 18082 --count 5040
dotnet run --configuration Release --project tools/DotNetJq.DifferentialProbe -- \
  --corpus regex
tools/verify-isolated-package.sh \
  --authors 'PUBLISHER DISPLAY NAME' \
  --repository-url 'https://github.com/OWNER/REPOSITORY'
```

Defaults:

- Reference checkout: `upstream/jq`; override with
  `DOTNETJQ_UPSTREAM`.
- Oracle: `artifacts/test-assets/jq-1.8.2/oracle/jq`; the managed-test harness
  honors `DOTNETJQ_ORACLE`, while each differential probe accepts
  `--oracle PATH`.

The upstream checkout and jq executable are verification inputs only. They are
not build, package, or runtime dependencies of `src/DotNetJq` or
`src/DotNetJq.Cli`.
