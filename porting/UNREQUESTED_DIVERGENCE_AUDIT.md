# Managed behavior and unrequested-divergence audit

Audit basis: jq 1.8.2 commit `34f7186b86743a083a589741b6cea95293524108`, the project `AGENTS.md`, `porting/PORTING_MANIFEST.json`, and `dotnetjq-port-spec.md`. The specification permits managed parser/printer/filesystem/regex/thread proxies only when behavior is proved, requires a controlled filesystem boundary, and adds execution limits only when their defaults do not compromise jq compatibility. Line references below describe the working tree audited on 2026-09-06 and may move as port work lands.

Classifications:

- **REQUIRED** — a managed host/proxy boundary or an exact pinned jq limit; it is not an added jq semantic.
- **USER** — explicitly requested by the user, including a documented product policy only where
  the user retained that policy after its jq discrepancy was made explicit.
- **EXTENSION** — an explicit, opt-in managed host policy authorized by the specification;
  it is not an upstream jq requirement, and its default must preserve jq behavior.
- **DIVERGENCE** — observable behavior or a core contract not authorized by pinned jq or the port specification.
- **CLOSED** — a divergence found during this audit whose repair is already present in the current working tree; retain the listed regression test.

## Release gate

This audit contains no remaining **DIVERGENCE** row. Each future repair must update implementation comments, `PORTING_MANIFEST.json`, status/audit documents, and tests in the same change, as required by `AGENTS.md`. The final gate is the unchanged official fixture suite plus differential execution against the pinned binary, targeted subprocess crash tests, exact refcount tests, package isolation, trim/NativeAOT smoke, and default-options parity. No production path may shell out to jq; the binary is a test oracle only.
